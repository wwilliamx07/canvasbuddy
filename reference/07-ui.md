# 07 — UI

Sources: `src/App.tsx` (state owner, builds the model), `src/ui/*` (the model, the hooks that produce parts of it, and the components that render it), `src/index.css`.

## One object in, pixels out

The UI is written against one type, `AppModel` (`src/ui/model.ts`). `App` collects its state and handlers into a `model: AppModel` and renders `<Shell model={model} />`; every component under `src/ui` takes the model (or a slice of it) as props and **nothing there reaches past it** — no `db/*` calls from components, no Canvas calls, no timers that pretend to be data. The only code under `src/ui` that touches the data layer or Chrome's permissions is the four hooks (`useMemoryExplorer`, `useConnectFlow`, `useConnections`, `useProviderAccess`), which exist to produce the model's `memory`, `connect`, `connections` and `providerAccess` sub-objects. `model.ts` itself re-exports static catalogues and types (`DEFAULT_FRESHNESS`, `PROVIDERS`, `modelInfo`, …) for Settings to render from.

The seam lets the look be rebuilt without touching the data layer: a new design is components over the same `AppModel`.

```
<App>                           owns: chats[], currentChatId, messages, apiHistory, contextDigests, loadedTools, chatUsage, contextMeasure,
 │                                    isLoading, settings, connection, notice; the agent loop (derives currentContextTokens)
 │  useConnectFlow(onConnected)   → model.connect      (tab inspection + grant; watches tabs only while disconnected)
 │  useMemoryExplorer(enabled)    → model.memory       (reads the graph; loads only once connected)
 │  useConnections()              → model.connections  (connection records from chrome.storage; also feeds App's tools)
 │  useProviderAccess(settings)   → model.providerAccess (host permission for a local / custom model provider)
 └── <Shell model>               header (logo · chat title ▾ · Memory · Settings) + notice banner + main
      ├── main = <CheckingPlaceholder> | <ConnectScreen> | <ChatArea>      by model.connection.status
      ├── <ChatListPopover>       under the title: chats (newest first), New chat, delete on hover
      ├── <MemorySheet>           slides over the chat; course list ⇄ course detail
      └── <SettingsSheet>         slides over the chat
```

`App` is the single owner of chat and settings state and, with `canvas/identity.ts` (the memory registry and the last identity per host), the only code that writes `localStorage` (connections live in `chrome.storage.local`, written by `connections/store.ts`). Sheets are local UI state in `Shell` (`sheet: 'memory' | 'settings' | null`); opening one does not change anything in the model.

## Connection

`App` owns `connection` (`checking` → `connected` | `disconnected`, internally carrying the profile and memory slot) and maps it to the model's three-variant `Connection` (`profileName`, `memoryName`). After settings load it auto-connects when no host is remembered (`findConnectableHost`: active tab, then known instances — whichever has permission and a live session) and otherwise checks the remembered `settings.canvasHost` against `chrome.permissions`, calls `activateCanvas(host)`, resolves the identity (`resolveIdentity`) and its memory slot (`memorySlotFor`), opens that database (`configureDatabase`) and loads that slot's chats. The system prompt is built from the profile's intro and the connected services (`buildSystemPrompt`).

The `notice` banner under the header (`model.notice = { text, reload }`) reports a signed-out session ("showing what's remembered for <name>") or another account signing in ("Reload to switch memory"), with a Reload button (`model.reload`), or that chats or settings could not be saved because storage is full (no button).

### Connect screen (`useConnectFlow` → `ConnectModel`, `Connect.tsx`)

Shown whenever `connection.status === 'disconnected'` (an unknown Canvas, a known one without a session, or the origin permission missing). There is no host field: the hook inspects the current tab (`inspectActiveTab`, re-run on `tabs.onActivated` / `onUpdated`, only while disconnected) and adds the profile name via `profileFor`. The screen shows one of: "open your Canvas site, then click the icon again" (no visible https URL), "<host> doesn't look like a Canvas site" with **Check again** (`connect.inspect`), or "Current tab: <host> · recognized as Quercus" with **Grant access to <host>** (`connect.grant`: request the origin first — Chrome needs the fresh gesture — then `verifyCanvasSession`; a `notCanvas` result releases the permission again; success calls `App`'s `handleConnected`). Errors show inline; `connection.reason` seeds the first one.

## Chat (`Chat.tsx`)

- User bubbles are plain text; assistant bubbles are Markdown through `renderMarkdown` (`utils/markdown.ts`: `marked` → DOMPurify allowlist → KaTeX placeholders swapped in after sanitizing, each formula first passed through `repairTex`; see `08-conventions-and-gotchas.md`) inside a `prose prose-sm` container. Links open in a new tab.
- **Streaming.** Each user turn gets one assistant bubble, created empty with `streaming: true` before the first model call and kept open across the turn's tool rounds: typing dots until the first step or token, then Markdown re-rendered per animation frame with a blinking caret (`.streaming-caret` in `index.css`). The loading row under the transcript shows only when no bubble is streaming (digesting, between a steering message and the next call). The timestamp appears once the bubble is finished, followed by the tokens the provider reported for the turn when it reported any (`Message.usage`, `formatUsage` in `ui/format.ts`: "4.1k in (3.2k cached) · 380 out (120 thinking)").
- **Steps.** `Message.steps` (thoughts and tool calls, filled by `App`; see `02-agent-loop.md`) render as one collapsible block at the top of the bubble (`StepsBlock`): "Working through N steps" while the run is on, "Worked through N steps" after. It is open while the assistant works and nothing is written yet, and closes when text arrives; a click on the header overrides that. Thoughts are Markdown through `renderMarkdown` in a muted italic (`.prose.thought` in `theme.css`); a tool step is its label with a spinner while running and an alert icon on error, and a chevron that reveals its arguments and result excerpt. With `settings.showReasoning` off, thought steps are hidden (also in older chats) and no longer requested.
- **Notices.** A `notice` step (a rate-limit wait) is a muted one-line row with a clock, spinning while it waits.
- **Approval.** A connection tool that changes something shows its step expanded with its arguments and **Allow** · **Always allow** · **Deny** (`model.respondToApproval`); the steps block stays open while a step is `awaiting`.
- **Keep going?** After `settings.toolRoundsBeforeAsking` (default 12) rounds of tool calls without an answer (and as many again after each "keep going") the run pauses and a card under the transcript says "N rounds of tool calls and no answer yet" with **Keep going** · **Stop here** (`model.continuePrompt` / `model.respondToContinue`). Stop here ends the turn with what the bubble has, no error; sending a message instead keeps it going and the message is read at once as steering; the composer's Stop aborts as usual.
- **Composer and steering.** Enter sends (Shift+Enter for a newline). The composer stays enabled during a run: a message sent then goes to the steering slot (`model.sendMessage`) and shows as a dashed user bubble at the end of the transcript, "Queued · read after the current step", with **Edit** (`model.editQueued` → the text back into the composer). While `isLoading` the composer shows a **Stop** button (`model.stop`: aborts the run, discards the queued message) and, when the draft is not empty, the Send button next to it.
- **Commands.** A draft that is `/` plus letters opens a suggestion list above the composer (`model.commands`, filtered by prefix): ↑/↓ move and load the highlighted command into the draft as `/name ` so arguments can be typed after it (the list stays filtered by the prefix originally typed until the next keystroke), Enter runs the picked command (or completes it when it needs arguments), Tab completes, Esc closes. `model.sendMessage` returns null when accepted, or the reason a command did not run, shown under the composer in the warning colour while the text stays. A command's outcome is a **notice row**: a muted, centred line between two rules (multi-line allowed), with its token usage when it made a model call. See `02-agent-loop.md` → Commands.
- Chats are titled from their first message. The chat list is a popover under the header title (`ChatListPopover`): select, delete, New chat. A chat is also created implicitly when a message is sent with no active chat. Leaving a chat while its answer is running stops the answer (`02-agent-loop.md` → Chat persistence).

## Memory (`useMemoryExplorer` → `MemoryModel`, `Memory.tsx`)

**Memory is managed entirely by the engine.** The sheet is a *view* of what the agent has remembered — it never syncs, refreshes or indexes anything, and offers no button that would. The only thing the user can do to memory is forget:

| Action | Where | What it calls |
|---|---|---|
| Forget everything (the graph) | foot of the Memory course list | `memory.forgetEverything()` → confirm → `forgetEverything` (`canvas/freshness.ts`: every table + `sync_state`, schema kept) → `reload()`. **Chats are kept.** |
| Forget this course | foot of the course detail | `memory.forgetCourse()` → confirm → `forgetCourse` (course row and everything under it, its documents, its sync stamps and the roster stamp so the course list refreshes next turn) → `reload()` |
| Delete this account's data | Settings → Canvas row | `model.deleteAccountData` → confirm → `closeDB` + `forgetMemory(slot)` (database, chats and the memory slot) + reload. Not a memory action: it removes everything CanvasBuddy holds for the account. |
| Forget one collection of a course | trash icon on a row of the course's collections table (hidden while the row says `not yet`) | `memory.forgetCollection(kind)` → confirm → `forgetCollection` (`canvas/freshness.ts`) → `reload()` |
| Forget one document's text | "Forget text" in the inspector of a file / page / assignment / discussion item that has text | `memory.forgetSelected()` → confirm → `forgetDocument` (`db/rag.ts`) → `reload()` |

Forgetting is not destructive to Canvas and not permanent: the engine fetches a forgotten collection again the next time a tool needs it, and a forgotten document is read again the next time a search or read targets it. What is gone is the local copy (and, for documents, the vector cache — see `05-rag.md`). Memory means the graph; chats are a separate thing and only "Delete this account's data" in Settings removes them.

Layout: the sheet root is the **course list** (six stat tiles from `getGraphStatistics`, one card per course, "Forget everything"); a card opens the **course detail** ("Forget this course" at its foot): name/term → the **collections table** (one row per course-scoped collection: label, count, sync pill `synced 12 min ago` / `hidden by course` / `not yet` / `failed`, forget) → Modules (collapsible, items with type icons and an indexed dot) → Assignments (due, points, submission state, score) → Pages → Files not in a module → Announcements → Discussions → Quizzes → Syllabus. Selecting a module item, assignment, page or file opens an inline **inspector** (type, id, due/points, "View in Canvas", and for nodes with text: "Text remembered (n chunks)" / "Text not read yet", Forget text, a chunk preview).

Data (`useMemoryExplorer(enabled)`; loads only while connected, since the database is not configured before that):
- Overview: `getGraphStatistics()`, `exploreGraph({ entity_type: 'courses' })`.
- Per course: `exploreGraph full_hierarchy` (tree), `exploreGraph assignments` with `include_submission`, `exploreGraph pages`, `getFilesList(courseId)` (loose files, and the `indexed` flag for every node via `docIdFor`), `listAnnouncements` / `listDiscussions` / `listQuizzes`, `getCourseSyllabus` → `hasSyllabus`, and `getSyncState(scopeKey(kind, { courseId }))` for the ten course-scoped kinds → `CollectionStatus[]` (`never` when there is no row, `unavailable`, `error` when the row carries an error, else `ok` + `syncedAt`; counts from the lists, `null` for home and syllabus).
- Selected node: `getFileChunks(docId)`.
- `reload()` re-reads everything; **`App` calls it after every agent turn** so the sheet shows what the turn brought in.

Status messages (`statusMessage`) are transient (4 s); `isForgetting` disables the forget controls while one runs.

## Settings (`Settings.tsx`)

`AppSettings` lives in `src/settings.ts` (with `DEFAULT_SETTINGS` and `normalizeSettings`, which maps the old flat `apiKey` / `baseUrl` / `model` / `embeddingModel` / `llmProvider` shape — an old OpenAI setting with a custom base URL becomes the `custom` provider):

```ts
{
  providers: Partial<Record<ProviderId, { apiKey, baseUrl? }>>,   // a key (and optional base URL override) per provider
  chat: { provider, model }, embedding: { provider, model },       // chosen independently
  contextThreshold, showReasoning, toolRoundsBeforeAsking, loadedToolsMax, loadedToolsTokenBudget, freshness?, canvasHost?
}
```

- Every field auto-saves on change (`model.updateSettings`) — there is no other mode. There is no footer; after each change a transient "Settings saved" `StatusLine` floats at the foot of the sheet (outside the scrolled content, so it is visible wherever the change was made) for ~1.5 s (a `useRef` timeout so rapid keystrokes reset it instead of stacking). Number fields are `NumberInput`: the text can be cleared and retyped freely, only a keystroke that leaves a valid value (within min/max, whole where required) is committed, and leaving the field with anything else shows the last committed value again — no clamping to the minimum while typing.
- **Canvas row**: "<host> · <profile> · <memory name>" with **Delete this account's data** and **Switch Canvas** (`model.disconnect` → releases the origin permission where possible, clears `canvasHost` and suppresses auto-connect for the session, which brings the Connect screen back; memory is kept), or "Not connected" while the Connect screen is showing.
- **Assistant**: rendered from the static catalogues re-exported by `ui/model.ts` (`PROVIDERS`, `providerInfo`, `modelInfo`, `isKnown768Embedding`):
  - **Chat provider** (every provider) and **Chat model** (placeholder = the provider's suggestion; with reasoning on, "This model does not share its reasoning" when `modelInfo` says so). Switching provider fills in the suggested model, except for local and custom servers.
  - **Embeddings provider** (only providers with an embeddings API) and **Embedding model**, with a note that it must give 768-d vectors and that changing it re-indexes documents as they are searched, plus a warning for a model not known to be 768-d.
  - One block per provider in use (chat and embeddings may share one): **API key** (show/hide; a non-blocking hint when the key lacks the provider's usual prefix; "Optional" for local and custom servers) and **Base URL** (empty = the provider default, shown as the placeholder; required for `custom`). Keys stay stored per provider, so switching back keeps them.
  - **Allow access**, shown while `model.providerAccess` (`useProviderAccess`) reports a missing host permission: a local server (Ollama, LM Studio: `http://localhost/*`, `http://127.0.0.1/*` are optional host permissions in the manifest) or a custom https base URL. Hosted providers answer CORS themselves and need none. The request runs from the click.
  - **Show the assistant's reasoning** (default **off**): thoughts are requested (`ChatRequest.thinking`) and shown as steps only when on, for models that share them.
  - **Tool rounds before asking** (`toolRoundsBeforeAsking`, 1–100, default 12): how many rounds of tool calls a reply makes without an answer before the "Keep going?" card (see Chat).
- **Connections** (`Connections.tsx`, `useConnections` → `model.connections`): one row per connection (name, host + `≈9k tokens of tools`, a pill: `N tools` / `off` / `sign-in needed` / `not working`, an enable checkbox; expanded: its tools, each with an on/off checkbox, its size, and `reads only` / `asks first` / `always allowed ×`, then Reconnect, Remove), **Sign in with <host>** when the server wants it, the error under a failed row. Below: catalog chips (Notion and Composio connect directly; Zapier explains where to get a personal URL), then URL + optional name + **Connect**. Each button that reaches a new origin asks Chrome for it first. See `09-connections.md`.
- **Connection tools** (collapsible, closed by default; `Disclosure` in `primitives.tsx`): one line on the current mode (`model.connections.toolLoading`: all tools sent because they fit in ≈2k tokens, or loaded on demand, with the total size), then **Loaded tools per chat** (`loadedToolsMax`, default 8) and **Loaded tools budget** (`loadedToolsTokenBudget`, default 6,000 tokens), and reset-to-defaults. They bound a chat's loaded set; see `09-connections.md` → Lazy loading.
- **Freshness** (collapsible, closed by default): one minutes field per row of `FRESHNESS_FIELDS` (`ui/model.ts`: the 13 collections plus probe debounce and unavailable retry) with a formatted hint and a reset-to-defaults button. Writes `settings.freshness`; the engine reads it on every `ensureCollection` call, so changes apply immediately.
- **Max context before summarization** (last on the sheet, which keeps bottom padding so the "Settings saved" line never covers it): slider + number, 5,000–1,000,000 tokens (whole numbers; the slider steps by 500), with a live meter of `currentContextTokens`: the provider's count of the last call plus an estimate of what was added since ("· counted by the provider"), or, with `contextTokensMeasured` false, all estimate ("≈", history plus declared tool schemas at ~4 chars/token). See `02-agent-loop.md` → Context management. **Compact now** (shown while `model.canCompact`: un-digested turns and no run in flight) runs `/compact`.
- Defaults: provider `google`, model `gemini-3.5-flash-lite`, embedding `gemini-embedding-2`, threshold 15,000, reasoning off, 8 loaded tools / 6,000 tokens, `freshness` = `DEFAULT_FRESHNESS`. Existing users keep whatever is persisted.

## Styling

- **Tailwind v4** via `@import "tailwindcss"` in `index.css`, with the typography plugin registered there as `@plugin "@tailwindcss/typography"` (Tailwind v4 ignores a `tailwind.config.js`; there is none). `index.css` also carries the root sizing, `.katex-display` overflow and the `.streaming-caret` animation.
- **Tokens** are CSS custom properties on the shell root (`.app { --bg … }` in `src/ui/theme.css`), used as `bg-(--bg)`, `text-(--ink)`: one palette (paper white, ink black, the logo's backpack blue `#004890` as the single accent, one warn and one error tone), one radius. `theme.css` also restyles `.prose` to the palette. Light only.
- **Type**: `Inter Variable` for text, `Fraunces Variable` (`.serif`) for headings and titles, both from `@fontsource-variable/*` and bundled into `dist` (nothing is fetched at runtime; the CSP is untouched).
- **Motion**: `motion/react` — `AnimatePresence` for sheets, the chat-list popover, inspectors, the steps block and Settings disclosures, `layout` on the chat list. Everything is ≤ 250 ms; the panel is a tool.
- **Logo**: `primitives.tsx` `Logo` crops `/logo.png` (the drawing sits in a known box on a white ground) and draws it with `mix-blend-mode: multiply` so the white disappears on the paper. The extension icon is `logo128.png`, the same drawing.
- The panel is narrow (Chrome's side panel is often ~400 px; Firefox's sidebar can be dragged narrower); everything is laid out for 340 px first. The shared primitives (`primitives.tsx`): `Sheet`, `Disclosure`, `Pill`, `Spinner`, `Logo`, `IconButton`, `EmptyState`, `StatusLine`, `NumberInput`, `UnderlineInput`, `SectionHeading`, `FieldLabel`.
