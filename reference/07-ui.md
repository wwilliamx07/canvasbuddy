# 07 — UI

Sources: `src/App.tsx` (state owner, builds the model), `src/ui/*` (the model, the hooks that produce parts of it, and the components that render it), `src/index.css`.

## One object in, pixels out

The UI is written against one type, `AppModel` (`src/ui/model.ts`). `App` collects its state and handlers into a `model: AppModel` and renders `<Shell model={model} />`; every component under `src/ui` takes the model (or a slice of it) as props and **nothing there reaches past it** — no `db/*` calls from components, no Canvas calls, no timers that pretend to be data. The only code under `src/ui` that touches the data layer is the two hooks (`useMemoryExplorer`, `useConnectFlow`), which exist to produce the model's `memory` and `connect` sub-objects.

The seam was chosen so the look can be rebuilt without touching the data layer: the mockups that produced this design were written over a mock `AppModel`, and porting one is copying its components and rewriting imports.

```
<App>                           owns: chats[], currentChatId, messages, apiHistory, contextDigests, isLoading,
 │                                    settings, currentContextTokens, connection, notice; the agent loop
 │  useConnectFlow(onConnected)   → model.connect   (tab inspection + grant; watches tabs only while disconnected)
 │  useMemoryExplorer(enabled)    → model.memory    (reads the graph; loads only once connected)
 └── <Shell model>               header (logo · chat title ▾ · Memory · Settings) + notice banner + main
      ├── main = <CheckingPlaceholder> | <ConnectScreen> | <ChatArea>      by model.connection.status
      ├── <ChatListPopover>       under the title: chats (newest first), New chat, delete on hover
      ├── <MemorySheet>           slides over the chat; course list ⇄ course detail
      └── <SettingsSheet>         slides over the chat
```

`App` is the single owner of chat and settings state and the only place that writes `localStorage`. Sheets are local UI state in `Shell` (`sheet: 'memory' | 'settings' | null`); opening one does not change anything in the model.

## Connection

`App` owns `connection` (`checking` → `connected` | `disconnected`, internally carrying the profile and memory slot) and maps it to the model's three-variant `Connection` (`profileName`, `memoryName`). After settings load it auto-connects when no host is remembered (`findConnectableHost`: active tab, then known instances — whichever has permission and a live session) and otherwise checks the remembered `settings.canvasHost` against `chrome.permissions`, calls `activateCanvas(host)`, resolves the identity (`resolveIdentity`) and its memory slot (`memorySlotFor`), opens that database (`configureDatabase`) and loads that slot's chats, and derives the session's system prompt from the profile.

The `notice` banner under the header reports a signed-out session ("showing what's remembered for <name>") or another account signing in ("Reload to switch memory"), with a Reload button (`model.reload`).

### Connect screen (`useConnectFlow` → `ConnectModel`, `Connect.tsx`)

Shown whenever `connection.status === 'disconnected'` (an unknown Canvas, a known one without a session, or the origin permission missing). There is no host field: the hook inspects the current tab (`inspectActiveTab`, re-run on `tabs.onActivated` / `onUpdated`, only while disconnected) and adds the profile name via `profileFor`. The screen shows one of: "open your Canvas site, then click the icon again" (no visible https URL), "<host> doesn't look like a Canvas site" with **Check again** (`connect.inspect`), or "Current tab: <host> · recognized as Quercus" with **Grant access to <host>** (`connect.grant`: request the origin first — Chrome needs the fresh gesture — then `verifyCanvasSession`; a `notCanvas` result releases the permission again; success calls `App`'s `handleConnected`). Errors show inline; `connection.reason` seeds the first one.

## Chat (`Chat.tsx`)

- User bubbles are plain text; assistant bubbles are Markdown through `renderMarkdown` (`utils/markdown.ts`: `marked` → DOMPurify allowlist → KaTeX placeholders swapped in after sanitizing; see `08-conventions-and-gotchas.md`) inside a `prose prose-sm` container. Links open in a new tab.
- **Streaming.** Each model turn gets its own bubble, created empty with `streaming: true` before the call: typing dots until the first token, then Markdown re-rendered per animation frame with a blinking caret (`.streaming-caret` in `index.css`). The loading row under the transcript shows only when no bubble is streaming (tool execution, digesting).
- **Activity.** A turn that ends in tool calls keeps its text and gets `activity`: one short line per call (`describeToolCall` in `App.tsx`), rendered under the text. Persisted with the chat; `streaming` is not.
- The composer sends on Enter (Shift+Enter for a newline); the Send button becomes **Stop** while `isLoading` (`model.stop` → `AbortController` in `App`).
- Chats are titled from their first message. The chat list is a popover under the header title (`ChatListPopover`): select, delete, New chat. A chat is also created implicitly when a message is sent with no active chat.

## Memory (`useMemoryExplorer` → `MemoryModel`, `Memory.tsx`)

**Memory is managed entirely by the engine.** The sheet is a *view* of what the agent has remembered — it never syncs, refreshes or indexes anything, and offers no button that would. The only thing the user can do to memory is forget:

| Action | Where | What it calls |
|---|---|---|
| Forget everything (the graph) | foot of the Memory course list | `memory.forgetEverything()` → confirm → `forgetEverything` (`canvas/freshness.ts`: every table + `sync_state`, schema kept) → `reload()`. **Chats are kept.** |
| Forget this memory (the account) | Settings → Canvas row | `model.forgetMemory` → confirm → `closeDB` + `forgetMemory(slot)` (database, chats and the memory slot) + reload |
| Forget one collection of a course | trash icon on a row of the course's collections table (hidden while the row says `not yet`) | `memory.forgetCollection(kind)` → confirm → `forgetCollection` (`canvas/freshness.ts`) → `reload()` |
| Forget one document's text | "Forget text" in the inspector of a file / page / assignment / discussion item that has text | `memory.forgetSelected()` → confirm → `forgetDocument` (`db/rag.ts`) → `reload()` |

Forgetting is not destructive to Canvas and not permanent: the engine fetches a forgotten collection again the next time a tool needs it, and a forgotten document is read again the next time a search or read targets it. What is gone is the local copy (and, for documents, the vector cache — see `05-rag.md`). Memory means the graph; chats are a separate thing and only "Forget this memory" in Settings removes them, because that action forgets the *account*, not just what was learned about its courses.

Layout: the sheet root is the **course list** (six stat tiles from `getGraphStatistics`, one card per course, "Forget everything"); a card opens the **course detail**: name/term → the **collections table** (one row per course-scoped collection: label, count, sync pill `synced 12 min ago` / `hidden by course` / `not yet` / `failed`, forget) → Modules (collapsible, items with type icons and an indexed dot) → Assignments (due, points, submission state, score) → Pages → Files not in a module → Announcements → Discussions → Quizzes → Syllabus. Selecting a module item, assignment, page or file opens an inline **inspector** (type, id, due/points, "View in Canvas", and for nodes with text: "Text remembered (n chunks)" / "Text not read yet", Forget text, a chunk preview).

Data (`useMemoryExplorer(enabled)`; loads only while connected, since the database is not configured before that):
- Overview: `getGraphStatistics()`, `exploreGraph({ entity_type: 'courses' })`.
- Per course: `exploreGraph full_hierarchy` (tree), `exploreGraph assignments` with `include_submission`, `exploreGraph pages`, `getFilesList(courseId)` (loose files, and the `indexed` flag for every node via `docIdFor`), `listAnnouncements` / `listDiscussions` / `listQuizzes`, `getCourseSyllabus` → `hasSyllabus`, and `getSyncState(scopeKey(kind, { courseId }))` for the ten course-scoped kinds → `CollectionStatus[]` (`never` when there is no row, `unavailable`, `error` when the row carries an error, else `ok` + `syncedAt`; counts from the lists, `null` for home and syllabus).
- Selected node: `getFileChunks(docId)`.
- `reload()` re-reads everything; **`App` calls it after every agent turn** so the sheet shows what the turn brought in.

Status messages (`statusMessage`) are transient (4 s); `isForgetting` disables the forget controls while one runs.

## Settings (`Settings.tsx`)

`AppSettings` lives in `src/settings.ts` (with `DEFAULT_SETTINGS`, `DEFAULT_BASE_URLS`, `normalizeSettings`, `resolveBaseUrl`):

```ts
{ apiKey, baseUrl, model, embeddingModel?, llmProvider: 'openai' | 'google', contextThreshold, freshness?, canvasHost? }
```

- Every field auto-saves on change (`model.updateSettings`) — there is no other mode. "Changes save automatically" sits at the foot of the sheet, and a transient **Saved** pill shows for ~1.5 s after each change (a `useRef` timeout so rapid keystrokes reset it instead of stacking).
- **Canvas row**: "<host> · <profile> · <memory name>" with **Forget this memory** and **Switch Canvas** (`model.disconnect` → releases the origin permission where possible, clears `canvasHost` and suppresses auto-connect for the session, which brings the Connect screen back; memory is kept), or "Not connected" while the Connect screen is showing.
- Provider, API key (show/hide; a non-blocking format hint — Google keys start with `AIza`, OpenAI with `sk-` — that stays quiet for OpenAI when a custom `baseUrl` is set), base URL (empty = provider default, shown as the placeholder), model, embedding model.
- Context threshold: slider + number, with a live meter of `currentContextTokens` against it (see `02-agent-loop.md` for what the estimate excludes).
- **Freshness**: one minutes field per row of `FRESHNESS_FIELDS` (`ui/model.ts`: the 13 collections plus probe debounce and unavailable retry) with a formatted hint and a reset-to-defaults button. Writes `settings.freshness`; the engine reads it on every `ensureCollection` call, so changes apply immediately.
- Defaults: provider `google`, model `gemini-3.5-flash-lite`, embedding `gemini-embedding-2`, threshold 15,000, `freshness` = `DEFAULT_FRESHNESS`. Existing users keep whatever is persisted.

## Styling

- **Tailwind v4** via `@import "tailwindcss"` in `index.css`, with the typography plugin registered there as `@plugin "@tailwindcss/typography"` (Tailwind v4 ignores a `tailwind.config.js`; there is none). `index.css` also carries the root sizing, `.katex-display` overflow and the `.streaming-caret` animation.
- **Tokens** are CSS custom properties on the shell root (`.app { --bg … }` in `src/ui/theme.css`), used as `bg-(--bg)`, `text-(--ink)`: one palette (paper white, ink black, the logo's backpack blue `#004890` as the single accent, one warn and one error tone), one radius. `theme.css` also restyles `.prose` to the palette. Light only.
- **Type**: `Inter Variable` for text, `Fraunces Variable` (`.serif`) for headings and titles, both from `@fontsource-variable/*` and bundled into `dist` (nothing is fetched at runtime; the CSP is untouched).
- **Motion**: `motion/react` — `AnimatePresence` for sheets, the chat-list popover, inspectors and message bubbles, `layout` on the chat list. Everything is ≤ 250 ms; the panel is a tool.
- **Logo**: `primitives.tsx` `Logo` crops `/logo.png` (the drawing sits in a known box on a white ground) and draws it with `mix-blend-mode: multiply` so the white disappears on the paper. The same file is the extension icon.
- The side panel is narrow (often ~400 px); everything is laid out for 340 px first. `Sheet`, `Pill`, `IconButton`, `EmptyState`, `StatusLine`, `SavedPill`, `UnderlineInput` and the section/field labels are the shared primitives.
